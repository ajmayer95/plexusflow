# plexusflow — method status, November 2026 (21S)

This document summarises where the mean-flow (DC) and pulsatile analyses stand for the 21-somite dataset. It covers which choices are final, what was tested and rejected, and how to reproduce the numbers. It accompanies the code on branch `dc-quasi-likelihood`. Stage data (graph, results, figures) live outside the repository: set `PLEXUSFLOW_STAGE` to a stage folder.

## 1. Pipeline in one paragraph

Each vessel segment is imaged by one or more tiles, i.e. separate recordings at slightly different times and heart rates. In every recording, the vessel's flux Q(t) comes from a per-frame Kloosterman profile fit; its time mean is the recording's mean flux. Recordings of the same vessel are averaged into one input per vessel, Q̄. The mean-flow field Q′ is the closest field to these inputs that conserves mass at every interior junction of the trusted plexus. Boundary inflows at the arterial cuts and the two vitelline veins are *outputs* of this reconstruction, not inputs. A passive Poiseuille network driven by the same boundary fluxes then tests how much of Q′ the vessel calibres explain (Fig 7). The pulsatile field and distensibility D are fitted on top of this (Figs 8–9).

## 2. Measurement uncertainty: the CV model (final)

The reconstruction needs a relative uncertainty per vessel. We use the recording's own temporal noise:

$$c_k = c_0 + c_{cv}\,\mathrm{CV}_k,\qquad \mathrm{CV}_k = \frac{\mathrm{SD}\big[Q_k(t) - \text{mean} - \text{3 cardiac harmonics}\big]}{|\overline{Q_k}|},\qquad \sigma_k = c_k\,|Q'_k| \oplus \sigma_0 .$$

- **Calibration:** c₀ = 0.29 and c_cv = 0.154, fitted by maximum likelihood on the mass imbalance of 4,562 junctions where every vessel was recorded by the same tile.
- **Variance at the reconstructed flux:** σ uses the reconstructed flux Q′ (a quasi-likelihood), not the measured value. Section 3 shows why that matters.
- **What it replaces:** an image-based "alignment" score. That model reconstructs equally well, but CV is directly observable and easier to justify. Alignment is kept as a sensitivity analysis.

## 3. Alternatives tested (identical scoring)

Same graph, same recordings; only the weighting differs. Scores use **all** held-out recordings:
- **Leave one recording out:** for each vessel recorded more than once, one recording is held out and predicted from the rest.
- **Withhold 10 % or 25 % of vessels:** every recording of those vessels is removed and their flux is predicted from the network.

The error is the median fold error |log(Q′/Q_held)|; lower is better. Source: `scripts/dc_uncertainty_models.py` → `results/dc_uncertainty_models.json`.

| model | weights | inflow (nL/s) | left share | held-out recording | 10 % withheld | 25 % withheld |
|---|---|---|---|---|---|---|
| average only | no conservation | – | – | ×1.844 | – | – |
| uniform projection | equal | 3.02 | 43 % | ×2.221 | ×2.572 | ×2.635 |
| fixed variance | σ = c\|Q̄\| (measured) | 2.76 | 45 % | ×2.412 | ×2.333 | ×2.254 |
| repeat-recording SD | σ from repeat agreement | 2.81 | 44 % | ×2.173 | ×2.383 | ×2.344 |
| constant c | σ = c\|Q′\| | 5.74 | 39 % | ×1.817 | ×2.021 | ×1.996 |
| **CV (primary)** | σ = (c₀ + c_cv·CV)\|Q′\| | **6.49** | **41 %** | **×1.779** | ×2.012 | ×2.019 |
| alignment | σ = (c₀ + c_a(1 − a))\|Q′\| | 6.52 | 39 % | ×1.793 | ×1.970 | ×2.005 |
| absolute + relative | σ² = α²Q′² + β²s² | 4.92 | 38 % | ×1.808 | ×1.995 | ×2.071 |

**What the table shows:**
- **Weights fixed from the measured value fail** (fixed variance, repeat SD, and uniform weights too). A vessel that reads low gets weight ∝ 1/Q̄², so under-reads, which are common, pull the whole network down. Total inflow halves and prediction worsens.
- **Evaluating the uncertainty at the reconstructed flux** (the last four rows) removes that bias.
- **Among those, CV, alignment and constant c perform similarly.** CV is chosen for simplicity and interpretability.
- **Heart-rate normalisation of fluxes is not used.** Recording gains vary 0.5–2.4× between tiles at nearly constant heart rate (tiles 21–53), so no heart-rate scaling law is defensible. Free per-recording gains, estimated from overlapping vessels, are reported as a sensitivity analysis.

## 5. Left/right split: what is and isn't identified

- **Reconstruction:** 38–41 % of arterial inflow enters on the left, whatever the uncertainty model.
- **Independent, gain-free comparisons give about 50–60 % left:**
  - the two aortae measured in the same recording;
  - the two vein outlets measured in the same recording;
  - the measured inlet vessels alone (54 %);
  - the reconstruction with free per-recording gains (50 %).
- **The discrepancy is recording-level gain.** Right-side recordings read high relative to overlapping recordings. The right side's largest inflow, 2.5 nL/s, enters at a cut whose only vessel is unmeasured, so it is inferred entirely from interior right-plexus measurements.
- **Forcing a 50/50 split is not supported by the data.** It routes about 1.3 nL/s through a corridor beside the left aorta, where 17 measured vessels read 0.0–0.4 nL/s. The passive comparison fits both versions equally well (r_log 0.67), so it cannot decide.
- **How we report it:** the reconstructed split, and the gain-free estimates, with the gap attributed to recording gain.

## 6. Reproducing

```bash
export PLEXUSFLOW_STAGE=/path/to/PlexusFlow21S
bash scripts/run_stage.sh "$PLEXUSFLOW_STAGE"        # DC reconstruction, validation, ablation, pulsatile field, D fit
python scripts/dc_uncertainty_models.py              # table in section 3
for n in 6 7 8 9; do python scripts/make_figure$n.py; done
FIG7_SYM=1 python scripts/make_figure7.py            # Fig 7 with the split forced to 50/50 (sensitivity)
python -m plexusflow.cli view "$PLEXUSFLOW_STAGE"    # read-only viewer
```

**Interpreter:** stage graphs are numpy-1 pickles, so use a numpy 1.x environment for anything that writes the graph.

**Viewer, Reconciled data source:** shows for every vessel its per-recording fluxes, the single averaged input to the reconstruction, the reconstructed Q′ and the 50/50 variant. It also has:
- boundary-node labels;
- an "edge flux card" (recordings → input → Q′, and the two end junctions);
- synchronised playback of two tile videos.
